PhyloAI spec audit issues
Generated: 2026-06-29
Scope: docs/superpowers/specs compared with current implementation. docs/superpowers/plans were treated as secondary context because they may be stale.

1. HIGH - `phyloai run` treats error payloads from substeps as successful steps.
   Spec: docs/superpowers/specs/2026-06-26-phyloai-run-design.md:386 says a failed step must mark the step failed, write top-level `status: "error"`, and exit 2.
   Code: phyloai/cli/commands/_run_pipeline.py:252 calls the runner and phyloai/cli/commands/_run_pipeline.py:267 unconditionally sets the step status to `success` if no exception was raised.
   Evidence: several library runners return `{"status": "error"}` instead of raising, e.g. phyloai/tree/msc.py:627, phyloai/tree/ml.py:800, phyloai/tree/ml_iqtree.py:1727.
   Impact: failed tree or downstream steps can be recorded as successful, causing resume/report/final result state to lie.

2. HIGH - `phyloai doctor` does not exit 3 when required tools are missing.
   Spec: docs/superpowers/specs/2026-06-18-phyloai-doctor-design.md:100 requires exit code 3 if a required tool is missing.
   Code: phyloai/cli/doctor.py:50 returns normally for JSON output, and phyloai/cli/doctor.py:66 renders text tables without checking required missing tools.
   Impact: automation cannot reliably gate external-tool workflows with `doctor`.

3. HIGH - Bundled-tool strategy is inconsistent with the doctor spec and package layout.
   Spec: docs/superpowers/specs/2026-06-18-phyloai-doctor-design.md:33 and docs/superpowers/specs/2026-06-18-phyloai-doctor-design.md:45 say TAPER `correction_multi.jl` and BMGE are bundled.
   Code/docs evidence: phyloai/core/env.py marks different tools as bundled/planned than the spec describes, while `phyloai/bundled/` is absent from the repository.
   Impact: users may be told no separate install is needed for tools that are not actually packaged or detected as bundled.

4. HIGH - `phyloai pretree metrics` does not run the default plot and correlation stages required by spec.
   Spec: docs/superpowers/specs/2026-06-14-pretree-metrics-design.md:15 describes Compute, Plot, and Correlate layers, and docs/superpowers/specs/2026-06-14-pretree-metrics-design.md:19 says all three execute by default.
   Code: phyloai/pretree/metrics.py:1057 builds and writes only the metrics table, and phyloai/pretree/metrics.py:1070 only records that table in `data.output_files`.
   Impact: expected PDFs, basic statistics, and correlation heatmap are missing from default runs and from `result.json`.

5. HIGH - `pretree metrics` can write non-standard top-level status `partial`.
   Spec: docs/superpowers/specs/2026-06-21-phyloai-json-output-standard.md:21 allows only `success | error`.
   Code: phyloai/pretree/metrics.py:1090 writes `partial` when any marker fails.
   Impact: report/MCP/automation consumers that key on the standard status set can misclassify runs.

6. MEDIUM - MCP `check_status` can report stale completion for a currently running resumed/reused output directory.
   Spec: docs/superpowers/specs/2026-06-27-phyloai-ai-integration-design.md:105 says `check_status` uses job/checkpoint/result state to determine `not_started | running | success | error | unknown`.
   Code: phyloai/mcp/tools/utils.py:18 returns `result.json` before checking `job.json` or a live PID.
   Impact: if a command resumes or reuses a directory with an old `result.json`, AI clients can see `success` while a new job is still running.

7. MEDIUM - MCP launch returns before `job.json` is written, so immediate status checks can say `not_started`.
   Spec: docs/superpowers/specs/2026-06-27-phyloai-ai-integration-design.md:104 says launch writes minimal `job.json` on launch.
   Code: phyloai/mcp/job.py:112 defers `job.json` writing to a background thread after the CLI creates `output_dir`; phyloai/mcp/tools/utils.py:23 reports `not_started` when `job.json` and `result.json` are absent.
   Impact: the documented AI workflow can produce a false `not_started` immediately after a successful launch.

8. MEDIUM - MCP `report` ignores `output_dir` and always overwrites.
   Spec: docs/superpowers/specs/2026-06-26-phyloai-report-design.md:562 documents report output directory support; skills/phyloai-workflow/SKILL.md:12 requires explicit approval before execution tools, especially overwrites.
   Code: phyloai/mcp/tools/cli_tools.py:56 always runs `phyloai report --run-dir ... --overwrite`; phyloai/mcp/tools/cli_tools.py:57 only reads `<run_dir>/report/report.json`.
   Impact: callers cannot choose report output path via MCP and existing reports can be overwritten unexpectedly.

9. MEDIUM - Dating MCMC `--ctl` conflicts are not enforced.
   Spec: docs/superpowers/specs/2026-06-25-phyloai-posttree-dating-design.md:116 says `--ctl` is mutually exclusive with non-default `--clock`, `--burnin`, `--sample-freq`, and `--nsamples`.
   Code: phyloai/posttree/dating_mcmc.py:407 accepts a supplied ctl and silently ignores those generated-ctl parameters.
   Impact: users can think their MCMC settings are applied when they are not.

10. MEDIUM - Single-command diagnostic capture often violates the JSON standard.
   Spec: docs/superpowers/specs/2026-06-21-phyloai-json-output-standard.md:205 requires merged stdout+stderr in `data.tool_stderr` for single external-tool commands.
   Code examples: phyloai/posttree/topology.py:879 captures only stderr, phyloai/tree/ml.py:792 hardcodes empty diagnostics for FastTree single mode, phyloai/tree/ml_iqtree.py:1719 hardcodes empty diagnostics for IQ-TREE single mode, and phyloai/tree/cf.py:1008 omits or drops some tool output.
   Impact: result.json loses diagnostic/progress output needed for reports and troubleshooting.

11. MEDIUM - `posttree topology --input-format` is effectively ignored.
   Spec: docs/superpowers/specs/2026-06-22-phyloai-posttree-topology-design.md:68 says this is a PhyloAI-side matrix format hint for preflight validation.
   Code: phyloai/cli/commands/posttree.py:317 performs only extension-style validation; phyloai/posttree/topology.py:45 only checks existence/readability.
   Impact: invalid or mismatched matrix formats are not rejected before launching IQ-TREE.

12. MEDIUM - IQ-TREE dry-run creates output directories.
   Spec expectation: dry-run commands validate and show commands without writing files; this is stated across command specs and help text.
   Code: phyloai/tree/ml_iqtree.py:1040 creates the single-mode output directory, and phyloai/tree/ml_iqtree.py:1257 creates batch `trees/` and `logs/` directories even during dry-run.
   Impact: dry-run can pollute paths and alter later overwrite/conflict behavior.

13. MEDIUM - Dating hessian error payloads are not JSON-standard complete.
   Spec: docs/superpowers/specs/2026-06-21-phyloai-json-output-standard.md:38 requires a full reproducible command; docs/superpowers/specs/2026-06-21-phyloai-json-output-standard.md:56 requires complete params.
   Code: phyloai/posttree/dating_hessian.py:175 creates validation/env error payloads with empty command/params, and phyloai/cli/commands/posttree.py:784 patches only command.
   Impact: failed runs cannot be reproduced or rendered accurately from `result.json`.

14. MEDIUM - `align --dry-run --resume` can reject a valid checkpoint due to executable-path normalization differences.
   Code: phyloai/pretree/align.py:713 and phyloai/pretree/align.py:752 store resolved executable paths in normal runs; phyloai/pretree/align.py:843 dry-run resume can validate against bare tool names from CLI/defaults.
   Impact: a dry-run resume intended to show remaining work can fail before reporting skip/rerun counts.

15. MEDIUM - Resumed/skipped successful align tasks produce invalid per-file wall times.
   Spec: docs/superpowers/specs/2026-06-21-phyloai-json-output-standard.md:119 says `files[].wall_time` must be a measured positive float when `cmd` is present; `0.0` is only valid for dry-run tasks.
   Code: phyloai/pretree/align.py:288 reconstructs skipped successful tasks with `cmd`, and phyloai/pretree/align.py:290 sets `wall_time: 0.0`.
   Impact: result.json violates the standard after resume and can fail strict consumers.

16. MEDIUM - `trim` can leave a misleading successful checkpoint when all tasks fail.
   Spec: docs/superpowers/specs/2026-06-12-checkpoint-resume-design.md:109 says checkpoint status should reflect failure/interruption accurately.
   Code: phyloai/pretree/trim.py:692 sets checkpoint status to `success` before phyloai/pretree/trim.py:708 checks whether all tasks failed.
   Impact: resume/report can treat a failed trim run as completed.

17. LOW - Resume log behavior is stale versus specs.
   Spec: docs/superpowers/specs/2026-06-11-pretree-align-design.md:177 and docs/superpowers/specs/2026-06-12-pretree-trim-design.md:343 describe appending resume runs with separators.
   Code: phyloai/pretree/align.py:925 and phyloai/pretree/trim.py:679 overwrite per-task logs.
   Impact: rerun provenance is lost, but command results can still be produced.

18. LOW - Skill parameter annotations are stale relative to runtime schemas.
   Spec: docs/superpowers/specs/2026-06-27-phyloai-ai-integration-design.md:179 says Skill version and parameter annotations are coupled to CLI changes.
   Example: skills/phyloai-workflow/references/parameter-annotations.md:133 describes `--trimal-method` as `gap/consistency/both/clipkit`, while current CLI/schema choices are `automated1/gappyout/strict/strictplus`.
   Impact: AI parameter cards can recommend invalid values even when runtime schemas are correct.

19. LOW - Report spec has stale scan-depth text.
   Spec: docs/superpowers/specs/2026-06-26-phyloai-report-design.md:110 says BFS scan default depth is 2.
   Code: phyloai/report/collector.py:121 uses `max_depth=3`, apparently to support nested outputs such as `runs/run/faa/tree/ml/iqtree/result.json`.
    Impact: likely documentation/spec drift rather than a code bug, but it should be reconciled.

## 回复

### 1. HIGH — FIXED
在 `_run_pipeline.py` 的 runner() 返回后增加检查：如果返回 `dict` 且 `status == "error"`，标记 step 为 "failed" 并抛出 `_RunStepError`。
文件：`phyloai/cli/commands/_run_pipeline.py:267+`

### 2. HIGH — FIXED
`doctor.py` 在 JSON 和 text 两种输出模式末尾都增加检查：如果任何 required 工具状态为 MISSING，`ctx.exit(3)`。
文件：`phyloai/cli/doctor.py:60+,80+`

### 3. HIGH — FIXED（代码）+ 待同步（spec/docs）
`env.py` 中移除了 iqtree3 和 trimal 的 `"bundled": True` 标记。`phyloai/bundled/` 已清空。TOOL_REGISTRY 与实际目录状态一致。
doctor spec 仍需同步更新以反映当前策略（不再捆绑工具，需外部安装）。

### 4. HIGH — 不用修 (audit 误报)
`pretree.py` CLI 层在 `run()` 返回后依次调用 `_generate_all_plots()` 和 `_compute_correlation()` + `_generate_correlation_heatmap()`（行 1117-1153）。audit 只检查了 `metrics.py:run()` 函数体，遗漏了 CLI 编排层。三个阶段确实都默认执行。
`plot` 和 `correlate` 子命令是为需要细调图的用户单独重跑的。

### 5. HIGH — FIXED
`metrics.py:1090` 将 `"partial"` 改为 `"error"`。
文件：`phyloai/pretree/metrics.py:1090`

### 6. MEDIUM — FIXED
`check_status` 重新排序：先检查 `job.json` + PID（检测是否正在运行），再查 `result.json`。避免旧 result.json 造成 stale completion。
文件：`phyloai/mcp/tools/utils.py:15-36`

### 7. MEDIUM — 接受偏离（不修代码，更新 spec）
产品取舍：job.json 延迟写入是刻意设计，避免在 CLI 创建 output_dir 前触发目录冲突检查。极端情况下可能有短暂 not_started（30s 超时），但实际影响极小。应从 spec 侧标记为"接受偏离"而非要求同步写入。

### 8. MEDIUM — 产品决定（更新 spec/skill）
MCP report 强制 `<run_dir>/report` + `--overwrite` 对 AI 场景是合理默认。偏离了 report spec 和 workflow overwrite 规则，但属于有意的产品取舍。需同步更新 spec 和 skill 文档。

### 9. MEDIUM — FIXED
`dating_mcmc.py` 增加互斥校验：当 `--ctl` 提供且 clock/burnin/sample_freq/nsamples 中有非默认值时，返回明确错误。
文件：`phyloai/posttree/dating_mcmc.py:394+`

### 10. MEDIUM — FIXED
4 处修复（覆盖所有 3 个 qCF 调用点和单模式路径）：
- `topology.py`: stdout+stderr 合并捕获
- `tree/ml.py:794`: 单模式 FastTree 使用 `first.get("tool_stderr")`
- `tree/ml_iqtree.py:1716`: 单模式 IQ-TREE 使用 `first.get("tool_stderr")`
- `tree/cf.py:936,986,1008`: 3 处 qCF 分支全部改为 `str(proc.stderr)`

### 11. MEDIUM — 接受现状（更新 spec）
`--input-format` 透传给 IQ-TREE 做校验是正确的。spec 中 "PhyloAI-side preflight validation" 描述应从 spec 中移除或改为说明"委托 IQ-TREE 校验"。功能本身没问题。

### 12. MEDIUM — FIXED
移除两个位置的 dry-run 目录创建：
- 单模式：删除 `output_dir.mkdir()` 行
- 批量模式：删除 `else` 分支中的 `trees_dir.mkdir()` 和 `logs_dir.mkdir()`
文件：`phyloai/tree/ml_iqtree.py:1040-1041,1255-1257`

### 13. MEDIUM — FIXED
hessian 3 处错误 payload 全部补全 `params` 字段：
- 输入验证错误（bin/check 阶段）
- seq_type auto-detect 失败时
- iqtree 路径解析失败时
`command` 字段由 CLI 层补齐。

### 14. MEDIUM — 接受已知限制
尝试修复后发现副作用过大（dry_run 时的非活动工具也被解析，影响多条测试和命令生成逻辑）。这是边界场景（dry_run + resume 同时使用），实际发生概率极低。暂接受为已知限制，如后续有实际用户报告再修复。

### 15. MEDIUM — FIXED
对从 checkpoint 恢复的 resume 任务，移除 `cmd` 字段（因未实际执行命令），`wall_time` 设为 `-1.0`（表示未测量）。避免伪造 cmd + 无效 wall_time 违反 JSON 标准。

### 16. MEDIUM — FIXED
将 all-fail 检查提前到 checkpoint 写入之前。如果当前批次和 resume 批次全为空，直接 raise 异常（不会写出 success checkpoint）。
文件：`phyloai/pretree/trim.py:692-693`

### 18. LOW — FIXED
更新 `parameter-annotations.md` 中 `--trimal-method` 的取值说明，从 `gap/consistency/both/clipkit` 更正为 `automated1/gappyout/strict/strictplus`。
文件：`skills/phyloai-workflow/references/parameter-annotations.md:134`

### 19. LOW — 不修代码
