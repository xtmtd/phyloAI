# PhyloAI Tree ML IQ-TREE Design Specification

**Date:** 2026-06-19
**Status:** Draft
**Parent spec:** `2026-06-17-phyloai-tree-design.md`
**Related spec:** `2026-06-07-phyloai-design.md`

---

## 1. Purpose

`phyloai tree ml iqtree` provides the IQ-TREE3 backend for maximum-likelihood tree inference. It covers homogeneous model workflows (with or without ModelFinder / partitions), heterogeneous model workflows (AA mixture, AA PMSF, NT MIX+MF; `--matrix` only), and branch support computation (UFBoot, SH-aLRT).

Two input modes:
- `--msa-dir`: directory of MSA files → batch parallel gene tree inference (homogeneous workflows only)
- `--matrix`: single concatenated matrix → supermatrix inference (all workflows)

## 2. CLI Parameters

Parameters are organized in functional blocks for `--help`.

### Input (mutually exclusive)

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--msa-dir` | Path | — | Directory of MSA files for batch gene tree inference |
| `--matrix` | Path | — | Single concatenated matrix for supermatrix inference |

IQ-TREE compatible input extensions: `.fa`, `.fas`, `.fasta`, `.faa`, `.fna` (FASTA); `.phy`, `.phylip` (PHYLIP); `.nex`, `.nxs`, `.nexus` (NEXUS); `.aln` (CLUSTAL). Unsupported files are recorded in `data.skipped`.

### Data Type

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--seq-type` | `AA\|NT\|auto` | `auto` | Molecule type. `NT` maps to `--seqtype DNA` for IQ-TREE. Other `--seqtype` values (BIN, NT2AA, CODON, MORPH) must be passed via `--tool-args` |

### Model Specification (when `--modelfinder none`)

When ModelFinder is not used, the substitution model is specified directly. `--model`, `--state-freq`, and `--rate-heterogeneity` combine to form the IQ-TREE `-m` argument string (e.g., `LG+F+R4`).

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--model` | str | `GTR` (NT) / `LG` (AA) | Substitution model. See model domains below. Defaults apply to homogeneous workflows only; heterogeneous workflows require explicit model |
| `--state-freq` | `+F\|+FO\|+FQ\|+FU\|none` | `+F` | State frequency type. `+FU` only valid for AA |
| `--rate-heterogeneity` | `+I\|+G4\|+I+G4\|+R4\|+I+R4\|none` | `+R4` | Rate heterogeneity among sites |

**`--model` domain by workflow:**

| Seq type | Workflow | Valid values |
|----------|----------|-------------|
| NT | Homogeneous | `GTR` (default), `HKY`, `JC`, `F81`, `K2P`, `K3P`, `K81uf`, `TN`, `TNef`, `TIM`, `TIMef`, `TVM`, `TVMef`, `SYM` |
| AA | Homogeneous | `LG` (default), `Poisson`, `cpREV`, `mtREV`, `Dayhoff`, `mtMAM`, `JTT`, `WAG`, `mtART`, `mtZOA`, `VT`, `rtREV`, `DCMut`, `PMB`, `HIVb`, `HIVw`, `JTTDCMut`, `FLU`, `Blosum62`, `GTR20`, `mtMet`, `mtVer`, `mtInv`, `FLAVI`, `Q.LG`, `Q.pfam`, `Q.pfam_gb`, `Q.bird`, `Q.mammal`, `Q.insect`, `Q.plant`, `Q.yeast` |
| AA | Heterogeneous (mixture) | `C10`–`C60`, `EX2`, `EX3`, `EHO`, `UL2`, `UL3`, `EX_EHO`, `LG4M`, `LG4X` |
| NT | Heterogeneous | `MIX+MF` |

### ModelFinder

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--modelfinder` | `MF\|MFP\|none` | `none` | `MF` = ModelFinder only (model selection, **no tree**); `MFP` = ModelFinder + tree search; `none` = use `--model` directly |
| `--mset` | str | `LG,WAG` (AA) / `GTR,HKY` (NT) | Comma-separated model list to restrict search. Use `all` for unrestricted |
| `--msub` | `nuclear\|mitochondrial\|chloroplast\|viral` | `nuclear` | AA model source. AA only; ignored for NT |

When `--modelfinder` is `MF` or `MFP`, `--model`, `--state-freq`, and `--rate-heterogeneity` are all ignored (ModelFinder determines the full model string including state frequencies and rate heterogeneity). In `result.json`, these three fields are recorded as `null` to indicate they were not passed to IQ-TREE. Use `--mset` to restrict the model search space. Advanced frequency/rate candidate control for ModelFinder (IQ-TREE `--mfreq`, `--mrate`) is available only through `--tool-args`.

When `--modelfinder MF` (model-only): no tree search, no branch support computation. Branch support flags (`--boot`, `--alrt`, `--bnni`) produce a warning and are ignored. The output `.iqtree` report contains the selected model; `.treefile` is **not** produced.

### Partitions (--matrix only)

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--partitions` | Path | — | Partition file (NEXUS or RAxML-style). RAxML-style partitions can be generated by `phyloai pretree concat`. Only valid with `--matrix` |
| `--rclusterf` | int (1–100) | — | % partition pairs for rclusterf merge algorithm. Mutually exclusive with `--rcluster-max` |
| `--rcluster-max` | int | — | Max number of partition pairs for rcluster merge. Mutually exclusive with `--rclusterf` |

If neither `--rclusterf` nor `--rcluster-max` is provided, defaults to `--rclusterf 10`. These only take effect when `--partitions` is present AND `--modelfinder` is `MF` or `MFP`.

IQ-TREE3 uses the `--merge` flag for partition merging (not the older `-m MF+MERGE` syntax).

### Heterogeneous Models (AA; --matrix only)

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--pmsf-base-model` | str | `LG` | Base AA homogeneous model for PMSF. Only valid when `--model` is C10–C60 |
| `--guide-tree` | Path | — | Guide tree for PMSF in NEWICK format. Required for PMSF mode. Maps to IQ-TREE `-ft` |

When `--model` is C10–C60 and `--guide-tree` is provided, PMSF mode is triggered: the base model is prepended to the mixture (e.g., `LG+C20+F+R4 -ft guide.nwk`). Without `--guide-tree`, direct mixture mode is used (e.g., `C20+F+R4`).

Heterogeneous workflows only support `--matrix` mode (single supermatrix). They produce an error if combined with `--msa-dir`.

### Heterogeneous Models (NT; --matrix only)

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--qmax` | int | `10` | Max rate categories for MIX+MF. Maps to IQ-TREE `-qmax`. Only valid when `--model` is `MIX+MF` |

Reference: <http://www.iqtree.org/doc/Complex-Models/> (section: Mixture models). NT heterogeneous only supports `--matrix` mode.

### Tree Search

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--mode` | `normal\|fast` | `normal` | `fast` maps to IQ-TREE `--fast` (fast search resembling FastTree) |

Note: The `--mode` domain is backend-specific. FastTree uses `normal|fastest|slow`; IQ-TREE uses `normal|fast`.

### Branch Support

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--boot` | int (>=0) | `1000` | UFBoot replicates (>=1000 recommended). Maps to IQ-TREE `-B`. `0` = skip branch support |
| `--alrt` | int (>=0) | *optional* | SH-aLRT replicates. Only passed to IQ-TREE when explicitly provided. `0` = parametric aLRT. Omit to skip SH-aLRT |
| `--bnni` | flag | `False` | Optimize UFBoot trees by NNI. Only when `--boot > 0`; warn and ignore otherwise |

By default, `--boot 1000` is enabled (matching `phyloai tree ml fasttree` behavior). Set `--boot 0` to skip UFBoot entirely.
If neither `--boot` (>0) nor `--alrt` is provided, no branch support is computed.
`--alrt` not provided → `--alrt` flag not passed to IQ-TREE (no SH-aLRT).
`--alrt 0` → `--alrt 0` passed to IQ-TREE (parametric aLRT).

### Output

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--rate` | flag | `False` | Write empirical Bayesian site rates to `.rate` file |
| `--wslr` | flag | `False` | Write site log-likelihoods per rate category to `.sitelh` file |
| `--constraint` | Path | — | Topological constraint tree in NEWICK format (multifurcating allowed). Maps to `-g` |
| `--outgroup` | str | — | Outgroup taxa, comma-separated. Maps to `-o` |
| `--prefix` | str | — | Prefix for output files. **Only valid with `--matrix`**; ignored (with warning) in `--msa-dir` batch mode where gene names are used as prefix |

### Execution

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `-o`, `--output-dir` | Path | `runs/tree/ml/iqtree` | Output directory |
| `--threads`, `-t` | `NUM\|auto` | `4` (batch) / `auto` (single) | Batch mode: number of parallel IQ-TREE jobs (each with `-T 1`). Single mode: maps to IQ-TREE `-T NUM` or `-T AUTO` |
| `--overwrite` | flag | `False` | Remove existing output directory before running |
| `--resume` | flag | `False` | Resume incomplete run (see Section 5) |
| `--dry-run` | flag | `False` | Print commands without executing |
| `--keep-extra` | flag | `False` | Batch mode: keep extra IQ-TREE output files (`.ckp.gz`, `.bionj`, `.mldist`, etc.) in `logs/`. By default only `.iqtree` and `.log` are kept |
| `-q`, `--quiet` | flag | `False` | Suppress all output except errors |
| `--iqtree-path` | Path | — | Custom path to `iqtree3` executable |
| `--tool-args` | str | — | Additional strategy arguments passed to IQ-TREE. See Section 9.9 of main design spec |

## 3. Workflow Classification

The workflow is determined by `--modelfinder` and `--model`:

```
                      ┌──────────────────────────────┐
                      │     --modelfinder 值？        │
                      └──────────────┬───────────────┘
                                     │
              MF/MFP ────────────────┼──────────── none
              (同质性)                │              │
                │                    │         --model 值？
          有partitions?              │              │
           │        │                │    ┌─────────┼─────────┐
          是       否                │  标准模型  Mixture   MIX+MF
           │        │                │  (GTR,LG,  (C10-C60,  (NT异质)
    --rclusterf  ModelFinder        │  WAG...)  EX2,EX3...)  ──matrix only
    或rcluster-max  +TreeSearch      │    │         │          │
     + --merge     (+Support if     │  同质性    AA异质    NT异质
     + ModelFinder  MFP mode)       │    │     ──matrix only  │
     + TreeSearch      │            │    │         │          │
     (+Support if      │            │    │    ┌────┴────┐     │
      MFP mode)        │            │    │  PMSF?   直接混合  │
                       │            │    │    │        │      │
    NOTE: MF mode      │            │    │  PMSF    直接     │
    produces no        │            │    │  模型    模型     │
    .treefile          │            │    │                   │
                       │            │    │                   │
                       └────────────┴────┴───────────────────┘
                                          │
                                     TreeSearch
                                      +Support
                                   (if MFP or none)
```

### Command Mapping Table

| Workflow | Input mode | PhyloAI parameters | IQ-TREE command |
|----------|-----------|-------------------|-----------------|
| 同质-无分区-none | both | `--model GTR --state-freq +F --rate-heterogeneity +R4` | `iqtree3 -s msa.fa -m GTR+F+R4` |
| 同质-无分区-MF (model only) | both | `--modelfinder MF --mset GTR,HKY` | `iqtree3 -s msa.fa -m MF --mset GTR,HKY` |
| 同质-无分区-MFP | both | `--modelfinder MFP --mset GTR,HKY` | `iqtree3 -s msa.fa -m MFP --mset GTR,HKY` |
| 同质-有分区-none | matrix | `--model LG --state-freq +F --rate-heterogeneity +R4 --partitions p.txt` | `iqtree3 -s msa.fa -p p.txt -m LG+F+R4` |
| 同质-有分区-MF (model + merge only) | matrix | `--modelfinder MF --partitions p.txt --mset LG,WAG --rclusterf 10` | `iqtree3 -s msa.fa -p p.txt -m MF --mset LG,WAG --merge --rclusterf 10` |
| 同质-有分区-MFP | matrix | `--modelfinder MFP --partitions p.txt --mset LG,WAG --rcluster-max 50` | `iqtree3 -s msa.fa -p p.txt -m MFP --mset LG,WAG --merge --rcluster-max 50` |
| AA异质-直接 | matrix | `--model C20 --state-freq +F --rate-heterogeneity +R4` | `iqtree3 -s msa.fa -m C20+F+R4` |
| AA异质-PMSF | matrix | `--model C20 --guide-tree g.nwk --pmsf-base-model LG --state-freq +F --rate-heterogeneity +R4` | `iqtree3 -s msa.fa -m LG+C20+F+R4 -ft g.nwk` |
| NT异质 | matrix | `--model MIX+MF --mset GTR,HKY --qmax 10` | `iqtree3 -s msa.fa -m MIX+MF --mset GTR,HKY -qmax 10` |

## 4. Validation Rules

1. `--msa-dir` and `--matrix` are mutually exclusive; exactly one must be provided

2. `--seq-type`: when `auto`, detect from input files via character set analysis. `NT` maps to IQ-TREE `--seqtype DNA`; `AA` maps to `--seqtype AA`; `auto` omits `--seqtype`

3. When `--modelfinder` is `MF` or `MFP`:
   - `--model`, `--state-freq`, `--rate-heterogeneity` are all ignored
   - `--mset` and `--msub` control the model search space

4. When `--modelfinder MF` (model-only):
   - No tree search, no `.treefile` produced
   - `--boot`, `--alrt`, `--bnni` produce a warning and are ignored
   - Success = model selected and `.iqtree` report written

5. `--model` domain (when `--modelfinder none`):
   - Homogeneous NT: only DNA standard models
   - Homogeneous AA: only Protein standard models (not `MIX+MF`)
   - AA data + `--model` in mixture set → AA heterogeneous workflow
   - NT data + `--model MIX+MF` → NT heterogeneous workflow

6. `--pmsf-base-model` and `--guide-tree`:
   - Only valid when AA data + `--model` is C10–C60
   - If `--guide-tree` is present → PMSF; otherwise → direct mixture
   - `--pmsf-base-model` accepts only AA standard (homogeneous) models

7. `--mset`:
   - AA + `--msub nuclear` → default `LG,WAG`
   - AA + `--msub` other → default `all` (no `--mset` passed to IQ-TREE)
   - NT → default `GTR,HKY`
   - Value `all` → no `--mset` passed to IQ-TREE

8. `--rclusterf` / `--rcluster-max`:
   - Only take effect when `--partitions` present AND `--modelfinder` is `MF` or `MFP`
   - Mutually exclusive
   - If neither supplied, default `--rclusterf 10`

9. `--partitions`:
   - Only valid with `--matrix`
   - With `--msa-dir`: exit with error

10. Heterogeneous workflows (`--model` mixture or `MIX+MF`): only valid with `--matrix`. With `--msa-dir`: exit with error

11. `--threads` / `-t`:
    - Batch mode (`--msa-dir`) default `4`: number of parallel IQ-TREE jobs, each with `-T 1`
    - Single mode (`--matrix`) default `auto`: maps to IQ-TREE `-T AUTO`
    - Must be int >= 1 or `"auto"`

12. `--boot` / `--alrt`:
    - `--boot` default `1000` (enabled, matching fasttree behavior); `--boot 0` skips UFBoot (no `-B` passed to IQ-TREE)
    - `--alrt` is optional; omit to skip SH-aLRT
    - `--alrt 0` is valid (parametric aLRT) and passed to IQ-TREE
    - `--bnni` only when `--boot > 0`; warn and ignore otherwise

13. `--keep-extra`:
    - Batch mode only; when enabled, preserves all IQ-TREE-generated files in `logs/`
    - By default only `.iqtree` and `.log` are kept per gene

13. `--overwrite` / `--resume` mutually exclusive

14. `--prefix`:
    - Only valid with `--matrix`
    - In `--msa-dir` batch mode: ignored with warning; gene names used as prefix internally

15. `--tool-args` two-tier handling per Section 9.9 of main design spec:
    - BLOCKED (hard-rejected): `-s` (input file), shell I/O redirects
    - OVERRIDEABLE (suppress-if-present in `--tool-args`): all flags PhyloAI generates (`-m`, `-p`, `-T`, `-B`/`--ufboot`, `--alrt`, `--bnni`, `--fast`, `--merge`, `--rclusterf`, `--rcluster-max`, `--mset`, `--msub`, `-ft`, `-g`, `-o`, `--rate`, `-wslr`, `-qmax`, `--seqtype`, `-q`, `-Q`, `-S`, `--redo`, `--redo-tree`, `--undo`; plus `--prefix` in single mode only)
    - Note: IQ-TREE `-q` (partition model) and PhyloAI `-q` (quiet) share a short flag but are orthogonal. `--tool-args "-q file"` is passed to IQ-TREE unchanged; PhyloAI's `-q` is handled at the CLI layer and never reaches the tool command.

## 5. Resume Behavior

- **Single MSA mode** (`--matrix`): repeat the identical IQ-TREE command. IQ-TREE natively handles resume via its own checkpoint mechanism (`--redo` handled by IQ-TREE).
- **Batch mode** (`--msa-dir`): use PhyloAI checkpoint system. Load `checkpoint.json`, skip completed gene trees (validated by `.treefile` existence and newick parseability), re-run failed/pending tasks.

Note: checkpoint params are hashed from resolved (effective) values — e.g., auto-detected `seq_type` rather than the literal `auto`. This ensures that if input files change between runs, the mismatch is caught; it also means a re-run with `--seq-type auto` on the same dataset produces a matching hash.

Checkpoint system reuses `phyloai/tree/checkpoint_helpers.py` (shared with fasttree). `_run_one_iqtree` returns status per task; `mark_task` and `plan_resume` handle tracking. For `--modelfinder MF` mode tasks, validate against `.iqtree` report existence instead of `.treefile`.

## 6. Exit Codes and Error Handling

| Code | Meaning |
|------|---------|
| `0` | Success (all tasks succeeded; for batch: at least one task succeeded; MF mode: `.iqtree` report produced) |
| `1` | User input error (bad parameter, file not found, invalid combination) |
| `2` | External tool failure (all IQ-TREE runs failed, or overall failure) |
| `3` | Environment error (`iqtree3` not found) |

**Partial failure in batch mode:** If at least one gene tree is produced, overall status is `success` with failed tasks recorded in `data.failed`. If all tasks fail, status is `error` with code `2`.

**No valid input:** If no valid MSA files found in `--msa-dir`, exit code `1`.

## 7. File Organization

### Code

```

├── __init__.py
├── ml.py                   # FastTree (existing)
```

| Function | Purpose |
|----------|---------|

| `_build_iqtree_cmd()` | Assemble IQ-TREE CLI argument list |
| `_run_one_iqtree()` | Execute IQ-TREE on a single MSA, parse `.iqtree` for result metadata, organize output files |

Shared helpers (reused from `ml.py` or extracted to shared module):
- `_scan_input()` — scan MSA directory (IQ-TREE extension set: `.fa`, `.fas`, `.fasta`, `.faa`, `.fna`, `.phy`, `.phylip`, `.nex`, `.nxs`, `.nexus`, `.aln`)
- `_validate_seq_types()` — sequence type detection and validation

### Output Directory

**Batch mode (`--msa-dir`)** — same layout as fasttree:

```
runs/tree/ml/iqtree/
├── trees/                         # gene trees
│   ├── <gene1>.treefile
│   └── <gene2>.treefile
├── logs/                          # per-gene IQ-TREE reports and supplementary files
│   ├── <gene1>.iqtree
│   ├── <gene1>.log
│   ├── <gene2>.iqtree
│   └── <gene2>.log
├── checkpoint.json
└── result.json
```

In batch mode, each gene task:
- Runs IQ-TREE with `--prefix <gene>` in a temporary per-gene working directory
- `.treefile` → `trees/<gene>.treefile`
- `.iqtree`, `.log`, and all other generated files → `logs/<gene>.<ext>`
- `--prefix` user flag is ignored (gene name used as prefix)

**Single MSA mode (`--matrix`)** — all IQ-TREE output files preserved in output directory root:

```
runs/tree/ml/iqtree/
├── <prefix_or_stem>.iqtree
├── <prefix_or_stem>.treefile
├── <prefix_or_stem>.log
├── <prefix_or_stem>.rate             # if --rate
├── <prefix_or_stem>.sitelh           # if -wslr
├── <prefix_or_stem>.ufboot           # if --boot
├── ... (all IQ-TREE native outputs)
└── result.json                       # data.tool_stderr inlined (single pattern)
```

Single mode uses `--prefix` if provided, otherwise the matrix file stem.

### Per-Task Result (`_run_one_iqtree` return)

```python
{
    "input": str,
    "output_tree": str | None,     # trees/<gene>.treefile or None if MF mode
    "log_iqtree": str,             # logs/<gene>.iqtree or <stem>.iqtree
    "log_file": str,               # logs/<gene>.log or <stem>.log
    "n_taxa": int,
    "log_likelihood": float | None,
    "model_selected": str | None,  # from ModelFinder (MF/MFP) or model string
    "cmd": list[str],
    "status": "success" | "failed" | "dry_run",
    "reason": str | None,
    "wall_time": float,
    "warnings": list[str],
}
```

For `--modelfinder MF` (model-only) tasks, `output_tree` is `None`; success is determined by `.iqtree` report existence and parseability.

- `log_likelihood`: for single mode only; `null` in batch mode (per-file values in `data.files`)
- `boot`, `alrt`: whether branch support was computed
- `partitioned`, `merged_partitions`: whether partitions and merge were used

### Parsing `.iqtree` for metadata

`model_selected` and `log_likelihood` are extracted from the `.iqtree` report file using best-effort regex matching. Multiple patterns are tried to handle variation across IQ-TREE versions and workflows.

| Field | Example in `.iqtree` | Regex patterns |
|-------|-------------------|----------------|
| `log_likelihood` | `Log-likelihood of the tree: -12345.678` | `Log-likelihood(?: of the tree)?:\s+([-\d.eE+]+)` |
| `log_likelihood` (alt) | `Log-likelihood: -1.234567e+04` | same pattern (scientific notation) |
| `model_selected` | `Best-fit model according to BIC: LG+F+R4` | `Best-fit model(?: according to \w+)?:\s*(\S+)` |
| `model_selected` (alt) | `ModelFinder will test \d+ models` (no single model) | not applicable; `null` |

Parsing failures yield `null` with no error. Raw matched lines preserved in `data` when parsing succeeds. When `--modelfinder` is `MF` or `MFP`, `model_selected` is the best-fit model from the `.iqtree` report; when `--modelfinder` is `none`, `model_selected` reflects the `model_string` derived from user parameters.
